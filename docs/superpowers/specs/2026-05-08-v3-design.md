# Job Alert v3 Design

**Goal:** Fix Snowflake's Playwright auth failure, eliminate short-keyword false-positives, and add per-job `first_seen` tracking so re-listed stale jobs never produce alerts.

**Architecture:** Three independent workstreams that touch different files and can be reviewed and tested independently. No new adapters, no new external services.

**Tech Stack:** Python 3.12, Playwright sync API, existing `requests`-based `HTTPClient`, `src/storage.py` for state persistence.

---

## Workstream 1 — Snowflake XHR Interception + page.evaluate Fallback

### Problem

`eightfold_playwright.py` currently passes HTTP cookies from `bootstrap_session()` to `HTTPClient.get()`. Phenom People (the SPA wrapping Eightfold at careers.snowflake.com) resolves tenant identity from localStorage/sessionStorage tokens that are set by JavaScript, not from HTTP cookies. The API returns `{"status":"failure","errorMsg":"Tenant not identified"}` because those tokens are absent from the replayed request.

### Approach

Two-tier strategy:

1. **XHR interception (primary):** During SPA boot, intercept the real `/api/apply/v2/jobs` network request the page makes. Capture its exact headers (including any tenant tokens, Authorization headers, etc.) and the first-page response body. Try replaying these headers via `HTTPClient` for pagination — this is fast and reuses existing code.

2. **page.evaluate fallback:** If the HTTPClient replay returns HTTP 401/403 or a JSON body containing `"errorMsg"` with an auth-shaped message, fall back to running `fetch()` calls directly inside the live Playwright page. The page context has full access to localStorage/sessionStorage, so all runtime tokens are automatically available.

### Files Modified

- **`src/browser.py`** — `BrowserSessionContext` gains two new fields; `BrowserClient` tracks the live page and gains `evaluate_fetch()`
- **`src/adapters/eightfold_playwright.py`** — auth strategy replaced with interception → HTTPClient → page.evaluate fallback

### `src/browser.py` Changes

#### `BrowserSessionContext` — new fields

```python
@dataclass(frozen=True)
class BrowserSessionContext:
    cookies: dict[str, str]
    headers: dict[str, str]               # response headers (existing)
    final_url: str
    captured_urls: tuple[str, ...]
    captured_request_headers: dict[str, str]   # NEW: request headers from intercepted XHR
    captured_first_response: str | None        # NEW: raw JSON body of intercepted response (page 1)
```

`captured_request_headers` is the allowlisted subset of headers the SPA sent. Same allowlist as existing headers: drop `:method`, `:authority`, `sec-fetch-*`; keep `Authorization`, `Origin`, `Referer`, `User-Agent`, `Accept`, `Content-Type`, and any custom tenant headers (non-prefixed, non-pseudo).

`captured_first_response` is the raw JSON string of the intercepted response body, or `None` if no matching XHR was observed during boot. Storing it avoids a redundant first-page API call.

#### `BrowserClient` — page lifecycle

`BrowserClient` gains `self._page = None` in `__init__`. After `bootstrap_session()` navigates and collects session data, the page is **not closed** — it stays open until `close()` is called. This enables the `evaluate_fetch()` fallback.

```python
def evaluate_fetch(self, url: str, params: dict) -> dict:
    """Run a fetch() call inside the live Playwright page. Returns parsed JSON."""
    if self._page is None:
        raise RuntimeError("No active page — bootstrap_session must be called first")
    js = """
    async (args) => {
        const p = new URLSearchParams(args.params);
        const resp = await fetch(args.url + '?' + p.toString(), {credentials: 'include'});
        return resp.json();
    }
    """
    return self._page.evaluate(js, {"url": url, "params": {k: str(v) for k, v in params.items()}})
```

`close()` closes the page (if open) before tearing down the browser context. Idempotent — safe to call multiple times.

#### `bootstrap_session()` — XHR interception

```python
def bootstrap_session(
    self,
    url: str,
    wait_for_selector: str | None = None,
    wait_for_response_url: str | None = None,
    timeout_seconds: int = 30,
) -> BrowserSessionContext:
```

Interception logic (when `wait_for_response_url` is provided):

```python
captured_request_headers: dict[str, str] = {}
captured_first_response: str | None = None

def handle_response(response) -> None:
    nonlocal captured_request_headers, captured_first_response
    # Use substring check — Playwright glob patterns differ from Python fnmatch
    if wait_for_response_url and wait_for_response_url.strip("*") in response.url:
        captured_request_headers = _filter_headers(dict(response.request.headers))
        try:
            captured_first_response = response.text()
        except Exception:
            pass

page.on("response", handle_response)
page.goto(url)
if wait_for_selector:
    page.wait_for_selector(wait_for_selector, timeout=timeout_seconds * 1000)
else:
    page.wait_for_load_state("networkidle", timeout=timeout_seconds * 1000)

self._page = page   # keep alive for evaluate_fetch fallback
```

The `response` event fires asynchronously during navigation; `handle_response` captures the first matching XHR. The adapter proceeds regardless of whether an XHR was observed — `captured_request_headers` may be empty, which forces the fallback path.

### `src/adapters/eightfold_playwright.py` Changes

Replace the current cookie-forwarding auth with the two-tier strategy:

```
fetch()
│
├─ bootstrap_session()
│   ├─ Navigate SPA
│   ├─ on("response") → capture request headers + page-1 JSON
│   └─ return BrowserSessionContext
│
├─ [page-1 JSON already captured?]
│   ├─ Yes: parse page 1 from captured_first_response; begin HTTPClient at offset=page_size
│   └─ No: begin HTTPClient at offset=0 (page 1 is first HTTPClient call)
│
├─ [HTTPClient relay — primary]
│   ├─ GET api_url with captured_request_headers (starting from correct offset)
│   ├─ Success? → parse and yield, paginate via HTTPClient
│   └─ Fail on ANY page (401/403/errorMsg)? → switch ALL remaining pages to fallback
│
└─ [page.evaluate fallback]
    ├─ self.browser.evaluate_fetch(api_url, params)
    ├─ Returns JSON dict
    └─ parse and yield, paginate via evaluate_fetch
```

#### Auth failure detection

A relay response is considered a failure if any of the following are true:
- HTTP status is 401 or 403
- Response JSON contains a top-level `"errorMsg"` key
- Response JSON contains `"status": "failure"`

On first failure, switch all subsequent pagination to `evaluate_fetch`. Do not mix paths mid-pagination.

#### Page-1 optimisation

If `session.captured_first_response` is not None, parse it directly as the first page of results. Skip the first HTTP/evaluate call. This avoids a duplicate network round-trip.

#### Exception handling

Same as v2: any exception during steps 1–5 calls `self.browser.capture_debug_artifacts(self.company, e)`, logs a warning, returns.

## Workstream 2 — Word-Boundary Fix for Short Keywords

### Problem

`filter_tech_role` and `filter_early_career` use `_phrase_in_text` (plain `str.find` substring match). Short tokens — `ml`, `pm`, `swe`, `tpm` — match inside unrelated words:

| Token | False-positive matches |
|---|---|
| `ml` | "html", "xml", "email", "similarly" |
| `pm` | "company", "template", "implement" |
| `swe` | "elsewhere", "answer" |
| `intern` | "international", "internalize" |

`ai` was already removed from `technical_role_keywords` in v2 for the same reason.

### Fix

In `src/filtering.py`, replace `_phrase_in_text` with `_word_in_text` in both `filter_tech_role` and `filter_early_career`. `_word_in_text` uses word-boundary regex `(?<![a-z0-9])<keyword>(?![a-z0-9])`.

Multi-word phrases ("software engineer", "machine learning") are unaffected — word boundaries apply only at the start and end of the whole phrase, not between words.

```python
# filter_tech_role — before
for kw in filters.get("technical_role_keywords", []):
    if _phrase_in_text(kw.lower(), raw):
        return FilterResult(True, f"tech keyword: {kw}")

# filter_tech_role — after
for kw in filters.get("technical_role_keywords", []):
    if _word_in_text(kw.lower(), raw):
        return FilterResult(True, f"tech keyword: {kw}")
```

```python
# filter_early_career — before
for kw in filters.get("early_career_keywords", []):
    if _phrase_in_text(kw.lower(), raw):
        return FilterResult(True, f"early-career keyword: {kw}")

# filter_early_career — after
for kw in filters.get("early_career_keywords", []):
    if _word_in_text(kw.lower(), raw):
        return FilterResult(True, f"early-career keyword: {kw}")
```

### Files Modified

- **`src/filtering.py`** — two one-line changes in `filter_tech_role` and `filter_early_career`

No config changes. No new keywords. No other files touched.

## Workstream 3 — Per-Job `first_seen` State Tracking

### Problem

Amazon (and other platforms) refresh the `posted_date` field on re-listed jobs. A job posted six weeks ago may appear as "Posted Today" in the API. The freshness filter (`freshness_hours: 48`) passes it, and the user gets an alert for a stale listing. The existing dedup (`seen_ids`) prevents *repeat* alerts, but cannot prevent the *first* alert on a job we haven't seen before — even if the actual opening has been stale for weeks.

The fix: record when we first encounter each job. If we've been tracking a job for longer than `freshness_hours` without alerting on it (e.g., it passed filters but was never successfully sent), mark it `stale_suppressed` and skip.

### State Schema Migration — v1 → v2

#### Current v1

```json
{
  "version": 1,
  "first_run_completed_at": "2026-05-01T00:00:00Z",
  "companies": {
    "Micron": {
      "last_checked_at": "2026-05-08T10:00:00Z",
      "seen_ids": ["micron::workday::ABC123", "micron::workday::XYZ456"]
    }
  }
}
```

#### New v2

```json
{
  "version": 2,
  "first_run_completed_at": "2026-05-01T00:00:00Z",
  "companies": {
    "Micron": {
      "last_checked_at": "2026-05-08T10:00:00Z",
      "seen_jobs": {
        "micron::workday::ABC123": {
          "first_seen": "2026-05-08T10:00:00Z",
          "last_seen": "2026-05-08T10:00:00Z",
          "alerted": true
        },
        "micron::workday::NEW001": {
          "first_seen": "2026-05-08T10:00:00Z",
          "last_seen": "2026-05-08T10:00:00Z",
          "alerted": false,
          "stale_suppressed": true
        }
      }
    }
  }
}
```

Key differences: `seen_ids` list → `seen_jobs` dict keyed by job ID. Each entry carries `first_seen`, `last_seen`, `alerted`, and optionally `stale_suppressed`.

### Migration Logic

Migration runs once in `load_state()` when `version == 1`. For each company:

1. Take the `seen_ids` list (or empty list if missing).
2. Create `seen_jobs` dict: `{id: {first_seen: migration_ts, last_seen: migration_ts, alerted: true}}` for each ID.
3. Drop `seen_ids`.
4. Preserve `last_checked_at`.

Top-level: preserve `first_run_completed_at`, bump `version` to `2`.

Write result atomically via existing temp-file + `os.replace` pattern immediately after loading. No alerts are triggered by migration.

```python
def _migrate_v1_to_v2(state: dict) -> dict:
    """Upgrade in-memory state dict from v1 to v2. Returns mutated dict."""
    migration_ts = datetime.now(timezone.utc).isoformat()
    for company_state in state.get("companies", {}).values():
        seen_ids = company_state.pop("seen_ids", [])
        company_state["seen_jobs"] = {
            jid: {
                "first_seen": migration_ts,
                "last_seen": migration_ts,
                "alerted": True,
            }
            for jid in seen_ids
        }
    state["version"] = 2
    return state
```

`load_state()` calls `_migrate_v1_to_v2(data)` when `data["version"] == 1`, then immediately calls `save_state()` to persist the new format before returning.

### Freshness Gate Logic

Replaces `get_new_jobs()` and `mark_seen()` in `src/storage.py` with a unified `classify_jobs()` function and separate `mark_alerted()` function.

#### `classify_jobs(jobs, company, state, freshness_hours, now) -> list[Job]`

Returns only the jobs that should proceed to Discord alerting. As a side effect, updates `seen_jobs` entries in `state` (in-memory only — caller saves state).

For each job:

| Condition | Action |
|---|---|
| `job.id` in `seen_jobs` AND `alerted=true` | Update `last_seen=now`. Skip (no alert). |
| `job.id` in `seen_jobs` AND `alerted=false` AND `now - first_seen > freshness_hours` | Update `last_seen=now`. Set `stale_suppressed=true`. Skip (no alert). Log reason in verbose mode. |
| `job.id` in `seen_jobs` AND `alerted=false` AND within window | Update `last_seen=now`. Include in output (alert candidate). |
| `job.id` not in `seen_jobs` | Create `{first_seen: now, last_seen: now, alerted: false}`. Include in output. |

`last_seen` is always updated when a job is observed, regardless of outcome.

#### `mark_alerted(jobs, company, state) -> None`

Called after Discord alert succeeds. Sets `alerted=true` for each job ID in `seen_jobs`.

#### `update_last_checked(company, state, now) -> None`

Updates `last_checked_at` for the company to `now`. Called once per company at the end of its processing loop, regardless of whether any jobs were alerted. Replaces the implicit `last_checked_at` update that was buried in the old `mark_seen`. Creates the company entry in `state["companies"]` if it doesn't exist yet.

#### `prune_seen_jobs(state, ttl_days, now) -> None`

Called once per run on startup (after migration, before the company loop). Evicts per-company `seen_jobs` entries where `last_seen < now - ttl_days`. The old `_MAX_SEEN_IDS = 5000` cap is removed.

```python
def prune_seen_jobs(state: dict, ttl_days: int, now: datetime) -> None:
    cutoff = now - timedelta(days=ttl_days)
    for company_state in state.get("companies", {}).values():
        seen_jobs = company_state.get("seen_jobs", {})
        to_remove = [
            jid for jid, entry in seen_jobs.items()
            if datetime.fromisoformat(entry["last_seen"]) < cutoff
        ]
        for jid in to_remove:
            del seen_jobs[jid]
```

### Verbose Logging

When `--verbose` is passed, `classify_jobs` logs each suppressed job with its reason:

```
Micron job micron::workday::ABC123 suppressed: already alerted
Micron job micron::workday::OLD999 suppressed: stale_suppressed (first_seen 72h ago, limit 48h)
```

## Invariants

- Only `src/browser.py` and `src/adapters/eightfold_playwright.py` import Playwright.
- `eightfold.py` is not modified — parser helpers imported by reference.
- A run with no `use_playwright: true` company never starts chromium.
- State file is always written atomically (temp + `os.replace`). No partial writes.
- The v2 schema migration never triggers alerts — it only reorganizes existing data.
- `stale_suppressed=True` prevents a job from ever re-entering the alert path, even after pruning clears it and it reappears with a fresh Amazon date.

**Note on the last invariant:** If a job's `seen_jobs` entry is evicted by pruning (after 180 days of `last_seen` absence), and the job then reappears (Amazon re-lists it), it will be treated as entirely new — `first_seen=now`, and it will alert if it passes filters. This is acceptable: 180 days without being seen is a strong signal the listing is gone; if it genuinely reappears it likely is a new opening.
